## 九、为什么「有时扣、有时不扣，一扣就全扣」（2026-10-20 新增防护）

### 机制

水表里的消费流水**不清掉就一直累加**。只有走完「85 采集 → 云端上传 → 86 清账」
设备才会把那笔流水归零。

- 结算成功：上报的是零用量 → 云端计费 0 → **0 元的单子不会出现在账单列表里**
  （所以「不扣的时候连账单都没有」是正常的，不是没结算）。
- 结算没走完（蓝牙断 / 关窗 / 进程被杀 / 上传被拒）：流水留在表里，用量继续累加。
  下一次任何一次**真实用量**结算，会把积压的用量一次性上报 —— 这就是「一起全扣」。

老版本的开阀前置 `ensure_idle()` 用的正是真实用量补结算，所以链路是：
**上次没结算 → 下次点开水 → 自动补结算 → 把积压的全扣了**。

### 现在的四层保护

| 层 | 做法 | 代码 |
|---|---|---|
| 1 | 进入结算就写 `pending_settle.json`，确认 `onCharge=00` 才删除 | `pending_mark/clear` |
| 2 | 每次收发先查链路，掉线自动重连重发（22/85/86/23） | `_send_rw` / `_query_rw` |
| 3 | 启动连上设备后：有标记或设备非空闲 → **先零用量补清账**；正在出水则跳过 | `self_heal()` |
| 4 | 关窗时若在放水/结算未收尾 → 先零用量关水再退出（最多 60 秒） | `close_window()` |
| 5 | 全局闸：任何结算非显式放行一律改零用量 | `ble_settle()` |

补清账找不到流水时会自动销掉标记，不会每次启动都白跑。

### 实测

```
注入 pending_settle.json → 启动 → 自动连表 →
[!] 自愈：发现未完成结算 onCharge=00 → 先做零用量补清账
[D] 补清账 85 → 上传 → 86 清账 → onCharge=00，upload=True
标记已删除；账单仍 2 笔 / 3.200 元；余额 x.xxx 元不变
```

## 十一、离线开阀研究结论（2026-10-21 实测）

**结论：本固件（KLCXKJ-Water，base42）无法真正离线开阀。开阀必须由云端签发的 downData 驱动。**

### 依据

1. **downData 结构**：48 字节 = 8B 头（每单不同）+ **32B 体（两笔订单完全一致）** + 8B 尾（每单不同）。
   32B 体用程序内已知的 AES/DES/3DES 密钥正反向都解不开 → 密钥在服务端/固件里，本地无法构造。
2. **重放实验**：把两笔历史订单的 downData 原样通过 `0x21` 下发（严格按在线顺序 23 → 21），
   设备两次都回 **`8109`**（拒绝），不进 `onCharge=01`，不出水。
   说明 downData 与会话/随机数绑定，不能复用。
3. **本地费率帧**：`0x17` / `0x31`（老固件离线路径）下发本地构造的 51B/33B 费率，设备一律不应答。
4. 被拒的 `21` 会让设备停在 `03 结算中`；随后 `22 → 85 → 86` 可以本地清回 `00`，
   全程未调用云端、未产生账单（实验后账单仍 2 笔 / 3.200 元，余额 x.xxx 元）。

### 实际能做到的“半离线”

- **开阀**：必须联网（rateOrder 拿 downData）。
- **使用中**：蓝牙断了也不影响出水，阀门由水表自己保持。
- **关阀**：蓝牙在就行；`86` 本地清账可用（不必等云端 clearCode 才回空闲）。
  但云端订单要等下次联网上传才会了结（押金退回）。

> 网上说的“能离线”，多半指老固件（FE FE 协议）那批表，或者指“使用中不需要网络”，
> 不是指这块表能在完全没有云端的情况下开阀。实验脚本：`离线实验2.py`。

## 十二、防呆安全层（2026-10-29）—— 开水状态下关机/杀进程/断电也不会被扣

### 12.1 解决什么问题

以前在“放水中”直接关机/关窗/杀进程，程序没机会发 `22 → 85 → 86`，
阀门一直开着、设备流水一直累加，等下一次结算就会按真实用量扣钱。

现在的原则：**只要阀门可能开着，就必须有人负责把它零用量关掉；主程序死了，还有看门狗；电脑关机，先关阀再关机。**

### 12.2 新增文件

| 文件 | 作用 |
|---|---|
| `valve_safety.py` | 会话日志 / 心跳 / 超时自动关阀 / 关机休眠拦截 / 启动自愈 |
| `valve_guard.py` | 独立看门狗进程（主程序死了、心跳超时、重启后由它关阀） |
| `safety_selftest.py` | 安全层自检（会话 / 关机钩子 / 假 BLE 看门狗，不碰真表） |
| `valve_session.json` | 运行数据：state=opening/open/closing/closed、pid、boot_ts、heartbeat、deadline |
| `valve_safety.log` | 安全层日志（谁在什么时候关的阀、为什么） |
| `valve_guard.log` | 看门狗日志（连接、结算、失败重试） |

### 12.3 行为矩阵

| 你怎么干 | 程序会怎么处理 |
|---|---|
| 点「关水」 | 零用量结算，正常关阀 |
| 点窗口关闭按钮 | 先零用量关阀；**关不掉就不退出**，窗口保留、看门狗继续重试 |
| Alt+F4 / 系统关闭窗口 | 拦截 `WM_CLOSE`：先零用量关阀，关完才真正关窗；关不掉窗口不关 |
| 任务管理器杀 `python.exe` / `pythonw.exe` | 看门狗 25 秒内发现 PID 死亡 → 连表零用量关阀 |
| 注销 / 关机 / 重启 | 主窗口拦截 `WM_QUERYENDSESSION`：阻止关机 → 关阀 → 自动继续关机/重启/注销 |
| 合盖 / 休眠 | 拦截 `PBT_APMSUSPEND`：阻止休眠 → 关阀 → 再休眠 |
| 程序崩溃 | 看门狗按“心跳超时”接管关阀 |
| 看门狗被杀 | 主程序每 10 秒检查一次，发现不在就重新拉起 |
| 核心 CLI 菜单按 [1]/[2] | 默认停用（裸 CLI 无保护）；需 `WV_ALLOW_LEGACY_CLI=1` 才放行 |
| 直接拔电/断电 | 下次登录时看门狗（已注册 HKCU Run 自启动）读日志发现 state=open → 零用量关阀 |
| 直接拔电/断电 | 下次登录时看门狗（已注册 HKCU Run 自启动）读日志发现 state=open → 零用量关阀 |
| 断电后先打开主程序 | 启动自愈先关阀，关完之前**拒绝再次开阀** |
| 开阀超时 / 费用超上限 | 主程序内定时器自动零用量关阀（默认 20 分钟 / 预计 3 元） |

### 12.4 快捷方式的变化（重要）

`开水.bat` / `关水.bat` 不再“直连水表、开完就退出”，而是：

1. 先检查本机安全控制台（`127.0.0.1:18801`）在不在；
2. 不在就用 `pythonw` 把 `WaterValveBLE_Web.py` 拉起来（窗口会出现）；
3. 通过 `/api/water/open`、`/api/water/close` 执行，控制台常驻监管；
4. **控制台起不来就拒绝开阀**——绝不会退回“开完就退出、阀门没人管”的裸开模式。

`关水.bat` 在控制台确实起不来时，才会做一次直连零用量关阀兜底（只关不开）。

核心命令行菜单 `python WaterValveBLE_v4.py` 里的 [1] 开阀 / [2] 关阀也默认停用了
（裸 CLI 没有看门狗、没有关机拦截）。确需绕过要显式：

```bat
set WV_ALLOW_LEGACY_CLI=1
python WaterValveBLE_v4.py
```

不推荐——这就是以前“开完把窗口一关，阀门没人管”的入口。

### 12.5 配置

`config.json` 里可加（首次启动会自动补默认值）：

```json
"max_open_minutes": 20,     // 最长连续放水分钟数，到点自动关
"max_cost_yuan": 3.0        // 按 12 L/min 保守估算的费用上限，到点自动关
```

### 12.6 自检（不碰真表、不关机）

```bat
cd /d D:\WaterValveBLE
python safety_selftest.py --data-dir %TEMP%\wv_safety_test
```

一次跑完：会话落盘 / 关阀状态机 / 启动自愈 / 开阀闸门 / `WM_QUERYENDSESSION` / `WM_CLOSE` / 假 BLE 看门狗结算。
也可分开跑：`--basic`、`--hooks`、`--guard`。

### 12.7 关闭安全层（不推荐）

| 环境变量 | 作用 |
|---|---|
| `WV_SAFETY=0` | 整体关闭安全层（回到旧行为，**不推荐**） |
| `WV_NO_GUARD=1` | 不启动外部看门狗 |
| `WV_NO_AUTOSTART=1` | 不注册登录自启动 |

自启动写在注册表（Unicode，中文路径不会乱码）：

```bat
reg query "HKCU\Software\Microsoft\Windows\CurrentVersion\Run" /v WaterValveGuard

```

### 12.8 残余风险（必须知道）

1. **拔电后、下次登录前**：看门狗无法运行，阀门只能靠设备自身的预扣（5 元）兜底；
   5 元 ≈ 200 升，设备用完预扣会自动停。登录后看门狗会立刻零用量清账。
2. **水表不在蓝牙范围**：看门狗会一直重试；在它连上之前，水会继续流（仍受 5 元预扣限制）。
   所以看到 `valve_guard.log` 里连续“连接失败”时，请靠近水表或手动关水。
3. **用手机官方 App 去关我们程序开的单**：手机会按真实用量结算 → 会扣钱。
   正确顺序永远是：先让本程序/看门狗零用量关阀，再用手机。
4. **Windows 强制断电/长按电源**：没有任何软件能在那瞬间执行关阀；只能靠第 1 条的设备预扣 + 下次登录自愈。

### 12.9 现场验证方法

1. 正常开一次水（人站在水表旁）；
2. 任务管理器结束 `python.exe`（或 `pythonw.exe`，主程序）；
3. 看 `valve_guard.log`：应在 25 秒内出现“需要收尾（主进程已退出）”→“结算返回 ok=True onCharge=00”→“收尾完成”；
4. 确认水表阀门已关、手机 App 账单没有新增消费。

> 验证时一定有人在表旁，别在洗澡中途做。

## 十三、精简与打包（2026-10-29）

### 13.1 安全层精简

- 心跳不再每 2 秒重写 `valve_session.json`，改为更新 `valve_heartbeat` 的 mtime；只有状态切换才落盘并 fsync。
- 看门狗空闲时只加载标准库 + `valve_safety`，真正要收尾时才 `import` `WaterValveBLE_v4` / bleak。
- 安全层代码不加密、不做混淆；注释只保留必要的设计说明。
- 自检独立到 `safety_selftest.py`，生产模块不再带测试代码。

### 13.2 打包方式

采用 PyInstaller **onedir**（不是 onefile）：

- onefile 每次启动都要解压到临时目录，启动慢、占内存；onedir 直接加载，实测本地 API 411ms 就绪、窗口 422ms。
- 不加密、不加壳；`--noconsole` 只是不弹黑框。
- 目录：`dist\蓝牙水库安全版\`，主程序 `蓝牙水库安全版.exe`，依赖在 `_internal`。
- 看门狗复用同一个 exe：主程序以 `--guard` 参数启动第二个进程，不额外做 exe。
- 自启动注册表指向 exe + `--guard`；源码运行则指向 `pythonw valve_guard.py`。
- 重新打包：双击 `build_onedir.bat`。

### 13.3 运行

```bat
dist\蓝牙水库安全版\蓝牙水库安全版.exe
```

首次运行会把 `config.json`（含账号/设备）复制到 exe 同目录；没有会话时按界面提示短信登录。

源码方式仍然可用：`1-启动(控制台).bat` / `2-启动(无窗口).bat`。

### 13.4 体积

当前 onedir 约 **34.5 MB**（含 pywebview / bleak / Crypto / Flask / Waitress）。onedir 不追求极限压缩：再压只会增加启动开销，且容易误伤 BLE/WinRT 依赖。

## 十四、v1.0.1 修复（2026-10-30）

### 14.1 开阀几秒就触发 ¥3 上限

根因是会话日志里上一轮的 `opened_ts` 没清：`before_open` 只写了新的 `started_ts`，watchdog 仍拿旧 `opened_ts` 算“已放水时长”，一开阀就判定已超 3 元。

修复：
- `before_open` 重置 `opened_ts / closed_by / close_attempts / guard_attempts`；
- 费用上限只在 `state=open` 时计算；
- `opened_ts < started_ts` 时按 `started_ts` 兜底。

### 14.2 复制日志

- Python 改用 Win32 剪贴板直写，不再依赖 `pyperclip`；新增 `POST /api/copy`。
- 前端按 `pywebview API → /api/copy → navigator.clipboard → textarea` 顺序降级，并检查每一步的返回值，失败会提示而不是假报成功。

### 14.3 自动滚动

- 滚到底部自动恢复跟随；向上滚动自动暂停。
- 暂停时按钮显示“⬇ 新日志 N”，点击回到底部并恢复。
- 详细/简洁切换、清空日志时重置跟随状态。

### 14.4 账本单价

- 设备流水 `费率=1925/25` 时取后一个当前费率 `25`，不再把 `1925` 当成单价，避免账本显示“官方会扣 ¥1.925”。
